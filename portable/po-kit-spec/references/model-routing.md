# Model and effort routing
Never name a model in an agent file or a brief. Pick it per task from measured complexity.

1. **Measure** the task from the files you already have (recon.md, the module md, the previous review): `screens`, `fields`, `roles`, `states`, `api`, `rules` (count of BR rows), `defects_prev` (defects of the last review of this module). Flags: `has_writes` (the task may create or edit data), `no_test_data` (lists are empty, so little to read), `money_or_legal` (payment, medical or personal-data rules), `independent_review` (reviewer must not share the writer's blind spots).
2. **Route**: `python3 -I scripts/route_model.py <tool> <task> screens=4 fields=30 roles=2 ...` with `<tool>` = the host you run in (`claude-code`, `codex`, `chatgpt`, or anything else: falls back to `default`). Tasks: recon, write, deepen, review, verify, export, translate. Output: score 0-100, `tier` (light, standard, deep), `effort` (low, medium, high), `model`, and `why`.
3. **Apply**: in Claude Code pass `model` (and `effort`, only when the tier file says the tool supports it) on the agent call; `inherit` means do not set it. In Codex put them in the agent/profile settings; in ChatGPT tell the user the tier and effort to pick in the model menu.
4. **Where model names live**: `scripts/models.json` (tier to name per tool). A team copy at `.po-kit/models.json` overrides it. When a vendor renames or adds models, edit that file only.
5. **Rules of thumb that stay fixed**: an independent review never runs on a lower tier than the writer of the same module; browser-driving tasks (recon, verify) never run on the light tier when `has_writes=1`; export and translate stay light.
6. **Calibrate**: after each task note `score`, tier, lint FAIL count and review defect count in the project's notes. If a tier keeps producing rework (lint FAIL > 3 or High defects > 2 on the first pass), lower the cut in the team `models.json` for that tier by 5-10 points.
