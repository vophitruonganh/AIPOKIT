# `config.json` for `build_srs.py` (copy `scripts/config.example.json`)
Language: `lang` = language of the generated document (shipped: `en`, `vi`; add more with `workflow `add-language``). `spec_lang` = language the spec text is written in (defaults to `lang`); it only affects actor/system wording heuristics.
Required: `product`, `version`, `cover_lines[]`, `date_line`, `files[]` (overview first, then module files without `.md`), `purpose` (`{product}` allowed), `out_of_scope`, `references[]`, `uc_permissions`, `external_actors_note`, `actors[]` (role names exactly as used in the spec; longest first is handled), `precondition`, `ui_layout`, `constraints[]`.
Optional: `role_map` {alias: actor}, `audit_note`, `scope_para_prefix`, `sections` {overview key: exact heading} (keys: product, glossary, reading, roles, conventions, navigation, modules, compliance, bugs, gaps), `legal_extra[]`, `plans_title`, `plans_note_prefixes[]`, `components_note_prefixes[]`, `dashboard_heading_regex`, `dashboard_title`, `lifecycle` {title,label_prefix,object,states,bad,edges,end} (drop to skip the state diagram), `overview_diagram` {actors,usecases,role_alias} (drop to derive from modules).
Template: `template` = `"classic"` gives the short classic SRS layout (HUST-style template): centered cover, section 1 with three parts, actors as prose, functions as a numbered list, use case diagrams and activity flows, then for each use case only the UC table (code, name, actors, description, trigger, precondition, main flow, alternate flows, postcondition), the input data table (STT, field, description, required, validation, example) and the business rules as notes; section 3 as bullets (UI, security, constraints); no appendices and no bug ids. Open questions and bugs stay in the full document (omit `template`) and in the PO sheet.
Wording: the cover (`cover_lines`), `purpose` and the overview describe the product, not the document's status or audience. Do not write lines such as "as-is SRS, draft for the PO to confirm" or "not yet a spec for developers"; how the survey was done (environment, host, accounts, browser, what was clicked, survey dates, records created) stays in `source/` and the run log, never in the spec or the SRS. `source_line` / `source_detail` are no longer used. Status of each rule is carried by its source label (Observed, Inferred, PO proposal, Unverified).
Add a language: `workflow `add-language` <code>`.
