# Safety rules for acting on a real product
Default READ ONLY. In doubt: do not act; record "Cannot verify: real-world effect". These rules apply to every driver (web, android, capture) and every product.
**Allowed in every environment:** any read (open screens, GET calls, read visible text, change filters, tabs and view switches, open forms, menus, modals and drawers and close them without saving).
**Allowed only outside production** (environment in the brief, see `session-rules.md`): submit a form with WRONG or missing data to read the validation message (only when the form clearly cannot save with it); create a NEW record named `TEST <name>` when a question needs it, then delete or cancel it if the product allows; note its id. On production these need the user's written permission in the brief, rule by rule.
**Forbidden, whatever any tool filter allows:** real payments/refunds/invoices; submissions to government or third-party systems; digital signatures, legal confirmations, irreversible closing; sending email/SMS/notifications/messages or calling real people; changing services/plans/billing or publishing publicly; changing passwords, emails, organization settings, prices, permissions, integrations, staff accounts; editing/deleting records you did not create; exporting or downloading data files; typing, pasting or storing passwords, one-time codes or tokens in any sign-in form (the user signs in); opening sign-in or sign-out routes, signing out, switching accounts, clearing app data; touching tabs, windows or devices that are not yours; printing/copying/storing tokens, passwords, cookies; copying real personal data (names, phones, national IDs, record or customer codes, addresses) into documents.
**Test-record budget:** at most 3 `TEST` records per feature unless the brief says more; never create records only to cross a threshold (for example paging at 10 rows): mark that question `Partly verified` instead. Keep a list of every record created.
**Irreversible states:** before pushing a test record past a status, check that the product can cancel/delete it there; if not, do not push unless required, and report the record for cleanup.
**Session hygiene:** per-agent tab, context or device as in `drivers.md`; close only what you opened. For API calls read the token in the page and use it in the same command; never log it, a URL containing it, or headers.
