# Phase details (read the section you need)
**P0 Prep.** `session-rules.md` first: driver + access preflight (no question), then one message: target(s)/version, purpose (as-is record, or basis for build/change/test: it decides the PO loop later), environment, roles to cover (one role only means Permission rows stay `Needs role`), forbidden list, personal-data rule, output templates, storage (Claude Doc with one tab per module, or markdown folder), languages. Write `brief.md` (no credentials in it, ever).
**P1 Recon.** Full walk per `coverage-rules.md` with the driver from `drivers.md`: every navigation item, sub-menu, tab, sub-tab, view switch, filter (all options), button, column, row action, form/modal/drawer (opened and closed without saving), detail view, state; one role at a time with a role checkpoint between roles; element sweep on each screen; one `inventory.md` row per element. Sitemap (group, screen, route or screen id, status). API (web driver): see `drivers.md`; enums from responses; roles from session/permission calls. Glossary (use / do not use). Script bundles only when needed (i18n keys, validation, flags). Everything unseen goes to Appendix C (not visible). Gate: `inventory_check.py` passes; every navigation item has a row; every API seen is in Appendix A (mobile: "API not visible"). Update run: `inventory_diff.py` (see `coverage-rules.md`).
**P2 Write.** One `spec-writer` per module, parallel (max 4 at once). 16 blocks, labels, numbered BR/AC/TC. Lint after each module. Gate: no FAIL.
**P3 Deepen.** Only features under the bar: main flow <5 steps, BR <5, no field table where the screen has inputs, TC <6 (core) or <3 (minor), no error flow. `spec_lint.py <md dir> --bar` lists them with the blocks to deepen; add only those blocks.
**P4 Verify.** Grouped by role (one role checkpoint per role), one `spec-verifier` and one tab or session per module. Per open question try a safe action; answer `Verified/Partly verified/Cannot verify`. Valid "cannot" reasons: real-world effect; other role needed; real people/calls; Product/Legal/Eng decision; no data; app bug. `PO proposal` becomes `Observed` when the app matches; if it differs keep `PO proposal (differs from current)`. Bugs go to the bugs table. Gate: no question left without one of the three prefixes. `Cannot verify` and `PO proposal` items go to the PO sheet (Phase 6), not to a separate user review.
**P5 Export.** See `export.md`.
**P6 PO loop (optional, see `po-loop-decision.md`).** `po_sheet_export.py` -> PO fills Decision/Answer/Decided by/Date -> `po_sheet_import.py --dry-run`, then for real (snapshot to `versions/v<old>/md`, answers as `PO decided <date> (<who>): ...`, rules relabelled, version + revisions bumped, `po-apply.md`, `po-verify.md`, `changes-v<old>-v<new>.md`) -> spec-writer aligns text -> lint -> `spec_diff.py` -> export. Keep INV, feature, BUG and rule ids stable between versions: add new ones at the end, never renumber.
**Pitfalls (seen on real runs).** A brief that forbids opening create/edit forms leaves every field Unverified (one run: 64 of 118 questions Cannot verify); recon that only lists top-level routes misses sub-features inside tabs and modals; an owner/admin account hides role bugs; signing in as another user in the person's browser ends their session (use a separate profile per role); the agent's own browser could not reach the target behind a proxy or allowlist (run the preflight); reusing a tab overwrote the person's work; a token printed in a log; a filter did not stop a real password-change request; invented numbers or statutes; doc export rate limits (one tab at a time); test records stuck in an irreversible status (clean up as you go); two agents on one tab (split by feature, read `sinceRev`, on `guard_mismatch` keep the other's content); a re-walk renumbered features and made the version diff useless (use `inventory_diff.py`).

## Tool notes (learned on real runs, any product)
- Tabs: give each agent its own tab, pass its id on every call, never reuse or close a tab you did not open. Some tools open a new tab even when given a tab id: navigate inside your tab by script (set the path or hash) and close extra tabs you caused.
- A script call that returns nothing or "browser not running": retry up to 3 times, then read the page text and mark what could not be tried as `Cannot verify: tool error`.
- Empty lists (no data for the account) leave most behaviours unverifiable: say so in Phase 0 and ask for an account with data, or (outside production) for permission to create clearly named TEST records.
- Sign-in pages, captchas and one-time codes are the user's job (`session-rules.md`). Never script them.
